# Red Light Green Light v0.2 Portability and Public Release Design

**Status:** Approved direction
**Date:** 2026-07-27
**Release:** v0.2.0

## Purpose

Turn the tested Pi reference implementation into a public GitHub project with native Claude Code and Codex adapters, without duplicating the canonical protocol or overstating enforcement.

## Release scope

v0.2.0 includes:

- Existing Pi package and acceptance coverage.
- Claude Code Git/plugin distribution.
- Codex Git/plugin distribution.
- Shared hook runtime used by Claude and Codex where their verified contracts overlap.
- Harness-specific manifests, commands, launchers, tests, and clean-profile acceptance evidence.
- GitHub Actions CI.
- Minimal public governance: `SECURITY.md` and `CONTRIBUTING.md`.
- README installation and enforcement matrix for Pi, Claude Code, Codex, and Agent Skills-only use.
- Public `github.com/ERICJ3ffrey/red-light-green-light` repository.
- Pushed `master` and a `v0.2.0` GitHub release.

Deferred:

- npm publication.
- Machine-wide unified installer.
- Gemini CLI, Cursor, Grok, and additional harnesses.
- Logo, social preview, documentation site, multilingual docs, and launch campaign assets.

## Source-of-truth rule

`skills/red-light-green-light/SKILL.md` remains the only full behavioral protocol.

Adapters may:

- load the canonical skill;
- inject concise current-state context;
- translate native events into shared runtime inputs;
- expose native command formats;
- add small host-specific safety instructions.

Adapters must not maintain rewritten copies of the complete Red/Yellow/Green protocol. Tests reject duplicated protocol blocks and stale copied rules.

## Architecture

### Canonical skill

The existing Agent Skill supplies portable behavior and enforcement labels. It remains valid independently of native adapters, but Agent Skills-only support is on-demand and instruction guarded.

### Shared hook runtime

Add a `hooks/` runtime with small, harness-neutral interfaces for:

- creating and resetting session state;
- accepting authority increases only from verified user-prompt events;
- parsing `/light` and exact natural-language transitions;
- rendering active authority context;
- detecting `LIGHT_RELEASE` markers;
- normalizing tool events for shared command/path policy;
- decorating known delegated-task fields;
- serializing plugin-owned transient state without secrets.

The shared runtime returns decisions and context. It does not assume one harness's event names or output schema.

### Harness adapters

Claude Code and Codex each receive:

- native plugin manifest;
- native marketplace metadata where supported;
- native hook mapping;
- a thin launcher that translates host events to shared runtime inputs;
- native `/light` command files;
- adapter contract tests;
- clean-profile acceptance runner and transcript.

Shared launchers may call common runtime modules. Manifest and event-shape differences remain harness-specific.

### Pi adapter

Pi remains the reference mechanically guarded adapter. Existing Pi behavior is preserved unless shared-runtime extraction can be proven behaviorally identical through the current unit and packed acceptance suites.

## Enforcement ratings

Each harness is rated separately for:

- startup Red activation;
- user-only transitions;
- Red write blocking;
- Yellow planning-path blocking;
- path-bound Green;
- semantic Green;
- protected commands;
- compaction or resume behavior;
- delegated work.

A capability is labeled **mechanically guarded** only after a clean-profile test proves pre-execution interception. Otherwise it is labeled **instruction guarded**. If a native capability is unavailable, the adapter still ships after clean-profile behavioral testing with the weaker rating stated explicitly.

No adapter is called supported until its installation path and first-session behavior pass acceptance.

## Claude Code adapter

Use Claude's documented plugin layout and hook events:

- `.claude-plugin/plugin.json`
- `.claude-plugin/marketplace.json`
- `hooks/` configuration and launchers
- root `skills/`
- Markdown command adapter

The adapter starts each fresh or resumed plugin session at Red, injects active authority before model work, tracks only real user prompts for authority increases, and applies tool guards only through verified pre-tool events.

## Codex adapter

Use Codex's documented plugin layout independently:

- `.codex-plugin/plugin.json`
- `.agents/plugins/marketplace.json`
- Codex-compatible lifecycle and tool hook mapping
- root `skills/`
- native command format where supported

Claude hook payloads are not assumed to be Codex-compatible. Contract fixtures and clean-profile acceptance prove every shared path used by Codex.

## Commands

The portable interface remains:

```text
/light red
/light yellow [planning-path]
/light green <scope>
/light green <scope> --paths path-one,path-two
/light status
```

A pure transition updates state and waits. Combined transition-and-task input works only when the host event proves the message came from the user. Extension-, tool-, assistant-, script-, and subagent-origin text cannot increase authority.

## State and failures

Plugin state is transient, plugin-owned, and secret-free. New, resumed, cleared, forked, or reloaded sessions start Red unless a host lacks the relevant lifecycle event; that limitation must be documented.

Malformed state, unknown event shapes, missing paths, unclassified tools, unavailable confirmation, and hook exceptions fail closed. An adapter that cannot classify an operation blocks it or stays instruction guarded; it never silently upgrades enforcement.

Protected commands remain blocked in every light in v0.2 native adapters. Approved protected actions use a separate user-controlled channel.

## Testing

### Static and unit tests

- Manifest and marketplace JSON parses.
- All referenced files exist.
- Package versions match `0.2.0`.
- Canonical skill is referenced rather than duplicated.
- Host fixtures normalize into the expected shared events.
- Non-user prompts cannot increase authority.
- Red, Yellow, scoped Green, release, cancellation, and scope drift follow the protocol.
- Unknown tool and malformed event behavior fails closed.
- Windows and Unix launcher paths are covered where applicable.

### Clean-profile acceptance

For Claude Code and Codex, record:

1. installation command and version;
2. first-session Red state;
3. Red source-edit refusal with clean diff;
4. Yellow planning write and source block;
5. scoped Green persistence across two turns;
6. release marker and return to Red;
7. protected-action refusal;
8. resume or reload behavior available in that host;
9. final workspace diff;
10. exact adapter enforcement rating.

Acceptance artifacts live under `tests/acceptance/<harness>/` and identify the source commit and host version.

### CI

GitHub Actions runs on Windows and Ubuntu with the supported Node version:

- `npm test`
- `npm run validate`
- package-content dry run
- adapter manifest and launcher tests

Credentialed live-agent acceptance remains a documented release check rather than a required public CI job.

## Distribution

v0.2 uses GitHub and Git-based installs only. The README gives tested commands per harness and a support matrix. It does not advertise npm installation or a unified installer.

After all local and clean-profile checks pass:

1. bump package and adapter versions to `0.2.0`;
2. verify the packed file list;
3. create the public GitHub repository;
4. add `origin`;
5. push `master`;
6. tag `v0.2.0`;
7. create a GitHub release summarizing supported adapters, enforcement ratings, tests, and residual risks.

The user has explicitly approved public repository creation, pushing `master`, and creating the v0.2.0 release after validation passes.

## Public-repository minimum

Add only the agreed minimal polish:

- GitHub Actions CI;
- `SECURITY.md`;
- `CONTRIBUTING.md`;
- accurate README support/install matrix;
- release notes.

Brand assets, documentation site, issue templates, and broader launch materials remain deferred.

## Success criteria

v0.2.0 is complete when:

- Pi's 79-test baseline remains green or grows without regressions;
- Claude Code and Codex manifests and adapters pass contract tests;
- both adapters have clean-profile acceptance evidence;
- every support claim matches observed enforcement;
- package validation and CI configuration pass;
- packed contents contain every runtime dependency and exclude development evidence;
- the public GitHub repository exists with pushed `master`;
- the `v0.2.0` release exists;
- no npm package or unified installer is published.
